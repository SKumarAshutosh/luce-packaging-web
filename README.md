# Lucè — Corrugated Box & Premium Packaging Website

A marketing site for a corrugated box manufacturer, **generated by Python**.

Content and settings live in two plain Python files. A build script renders
them through Jinja2 templates and writes a normal static site into `docs/` —
which GitHub Pages hosts **free**, on your own domain, with HTTPS.

```
config.py + content.py  ──▶  build.py  ──▶  docs/  ──▶  GitHub Pages
   (what you edit)          (Jinja2)      (generated)     (your domain)
```

---

## 1. One-time setup

```powershell
python -m pip install -r requirements.txt
```

That installs Jinja2, the only dependency.

---

## 2. Put your real details in

Open **[`config.py`](config.py)** — this is the only file you need to touch to
go live:

```python
WHATSAPP      = "919999999999"                 # country code + number, digits only
PHONE_DISPLAY = "+91 99999 99999"              # how it looks on the page
PHONE_DIAL    = "+919999999999"                # what the call button dials
EMAIL         = "hello@luce-packaging.com"
ADDRESS_LINE  = "Plot No. 00, Industrial Area, Your City"
GSTIN         = "00AAAAA0000A1Z0"              # or None to hide the line
DOMAIN        = None                           # "lucepackaging.com" once you have it
GITHUB_USER   = "your-username"
```

Then rebuild:

```powershell
python build.py
```

One value in `config.py` updates **every** place it appears — top bar, quote
section, footer, WhatsApp button, `CNAME`, `robots.txt`, `sitemap.xml`, the
canonical URL, the Open Graph tags and the Google structured data.

> **WhatsApp number format matters.** Full international form, no `+`, no
> spaces, no dashes. For India that's `91` + your 10 digits. If it isn't valid,
> the build says so and the chat buttons fall back to the quote form instead of
> opening a dead link.

### ⚠️ Replace the placeholder numbers

The four hero stats in [`content.py`](content.py) are **illustrative**:

```python
STATS = [
    {"label": "Years in packaging",    "count": 12, "suffix": "+"},
    {"label": "Boxes produced yearly", "count": 20, "suffix": "L+"},
    ...
]
```

Put your real figures in before publishing. The spec table figures
(bursting strength, GSM, safe load) are standard industry ranges — check them
against what your plant actually produces.

## 3. Preview it

```powershell
python build.py --serve
```

Opens at <http://localhost:8000>.

While you're editing, this is nicer — it rebuilds by itself every time you save
a file:

```powershell
python build.py --watch
```

Then just refresh the browser. (No caching gets in the way; the dev server
sends `Cache-Control: no-store`.)

To test on your phone, find your PC's IP with `ipconfig` and open
`http://<that-ip>:8000` on the phone. Same Wi-Fi network.

## 4. Changing content — no HTML needed

Everything is a Python list or dict in [`content.py`](content.py).

**Add a product** — append to `PRODUCTS`:

```python
{
    "tag": "New",
    "title": "Corrugated Rolls",
    "image": "prod-rolls.svg",          # put the file in static/img/
    "alt": "Rolls of corrugated board",
    "body": "Continuous board for wrapping odd-shaped goods.",
    "points": ["2-ply and 3-ply", "Any width to 1.6 m", "Cut to length"],
},
```

**Add an FAQ** — append to `FAQS`:

```python
{"q": "Do you offer credit terms?", "a": "Yes, after the first three orders."},
```

**Change a heading, a step, a capability** — they're all in there as text.

Run `python build.py` and the page regenerates.

### Two things worth knowing

- **Ampersands in headings.** Fraunces (the serif font) draws `&` as a
  decorative swash at heading sizes, which reads as a symbol rather than an
  ampersand. The `amp()` macro automatically renders any `&` in a serif heading
  using the body font — so just type `&` normally in `content.py`.
- **HTML inside text.** Fields are escaped by default. Where a snippet of
  markup is intentional (like `<em>light</em>` in the About paragraphs) the
  template applies `|safe`. Those fields are `PRODUCTS[*]["body"]` and
  `ABOUT["paragraphs"]`.

## 5. Deploy to GitHub Pages

### First time

```powershell
python build.py                # make sure docs/ is current
git add -A
git commit -m "Build site"
git remote add origin https://github.com/<username>/<repo>.git
git push -u origin main
```

Then on github.com: repo → **Settings** → **Pages**

- Source: **Deploy from a branch**
- Branch: **main**, folder: **`/docs`**  ← not `/ (root)`
- **Save**

Live in about a minute at `https://<username>.github.io/<repo>/`

The repo must be **Public** — free GitHub Pages doesn't serve private repos.

### Every time after

```powershell
python build.py
git add -A
git commit -m "Update prices"
git push
```

> `docs/` **is committed on purpose.** GitHub Pages serves the built files
> directly, so they have to be in the repo. Always run `python build.py` before
> committing, or your changes won't appear on the live site.

## 6. Your custom domain

**Step 1** — set it in `config.py` and rebuild:

```python
DOMAIN      = "lucepackaging.com"
GITHUB_USER = "your-username"
```

```powershell
python build.py
```

This writes `docs/CNAME` and switches every URL on the site to your domain.

**Step 2** — get the DNS records:

```powershell
python build.py --dns
```

Add what it prints at your registrar (GoDaddy, Hostinger, Namecheap…):

| Type | Name | Value |
|---|---|---|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| CNAME | `www` | `<username>.github.io` |

⚠️ **Delete any existing `A` or `CNAME` records on `@` first.** Leftover
parking-page records will stop the domain resolving.

**Step 3** — commit, push, then repo → Settings → Pages → **Custom domain** →
your domain → Save.

**Step 4** — once the DNS check passes (10 minutes to a few hours), tick
**Enforce HTTPS**. The certificate is free.

## 7. Project structure

```
corrugated-box/
├── config.py            ← your details: contact, domain, SEO       EDIT THIS
├── content.py           ← all page copy: products, FAQs, specs     EDIT THIS
├── build.py             the generator (build / serve / watch / dns)
├── requirements.txt     Jinja2
│
├── templates/           Jinja2 templates
│   ├── base.html        head, header, footer, WhatsApp button
│   ├── index.html       the page sections
│   ├── 404.html         not-found page
│   └── macros.html      icons, logo, ampersand handling
│
├── static/              source assets, copied into the build as-is
│   ├── css/style.css    all styling; design tokens at the top
│   ├── js/main.js       nav, reveals, counters, quote composer
│   └── img/*.svg        logo, favicon, 4 product illustrations
│
└── docs/                GENERATED — do not edit by hand
    └── (GitHub Pages serves this folder)
```

Anything you write in `docs/` gets overwritten on the next build. Edit
`templates/`, `static/`, `config.py` or `content.py` instead.

## 8. How the quote form works

No backend, nothing stored, nothing to maintain. On submit the form:

1. checks name and phone are filled in
2. assembles a readable enquiry from the fields you completed
3. opens **WhatsApp** with that message pre-typed — or your **email** app

You just hit send.

**Want enquiries emailed automatically instead?** Create a free
[Formspree](https://formspree.io) form, then in `templates/index.html` add
`action="https://formspree.io/f/YOUR_ID" method="POST"` to the
`<form id="quoteForm">`, and delete the `form.addEventListener('submit', …)`
handler in `static/js/main.js` so the browser submits normally.

## 9. Design changes

All colours, fonts and spacing are CSS custom properties at the top of
[`static/css/style.css`](static/css/style.css):

```css
:root {
  --sun:  #D9902A;       /* the orange from your logo */
  --blue: #1479C4;       /* the blue "è" accent       */
  --ink:  #17130F;       /* body text                 */
  --kraft-100: #F2EADC;  /* kraft paper backgrounds   */
}
```

Change one value there and it updates everywhere — buttons, badges, icon tiles,
table chips, the 3D hero box, all of it.

## 10. The social preview image

`static/img/og-image.svg` is a vector, and **WhatsApp, Facebook and LinkedIn
don't render SVG link previews**. `config.py` already points `OG_IMAGE` at a
`.png`, so export it once:

```powershell
npx sharp-cli -i static/img/og-image.svg -o static/img/og-image.png --width 1200
```

Or open the SVG in a browser and screenshot it at 1200 × 630. Drop the PNG in
`static/img/` and rebuild — until then the link preview shows no image.

## 11. What's built in

- Responsive from 320 px to wide desktop
- Sticky header, mobile drawer nav, scroll-linked active section
- Pure-CSS 3D corrugated box in the hero — no images, no library
- Scroll reveals and counting stats, both disabled under
  `prefers-reduced-motion`
- Keyboard accessible: skip link, visible focus rings, labelled fields,
  `aria-live` status messages
- Renders fine with JavaScript blocked — nothing stays hidden
- Print stylesheet, so a customer can print the spec sheet cleanly
- `LocalBusiness` structured data, Open Graph tags, sitemap, robots.txt
- Templates use `StrictUndefined`, so a typo in a template name fails the build
  instead of silently rendering a blank
